# Как обновить браузерный эталон

Эта процедура применяется только при новом независимом наблюдении браузера.
Зелёный тест старого снимка сам по себе не является поводом менять эталон.

1. Получите новое наблюдение настоящего браузера. Зафиксируйте версию, дату,
   окружение и способ захвата/разбора.
2. Сохраните исходные данные, необходимые для повторения измерения. Не выводите
   версию браузера только из имени предполагаемой спецификации.
3. Сравните нормализованный fingerprint и отдельные поля/параметры. Один итоговый
   хеш не заменяет диагностические assertions.
4. Если профиль изменился, добавьте новую версионированную спецификацию и
   независимый эталон. Исторические спецификации не переписывайте так, будто они
   всегда описывали новый браузер.
5. Обновляйте `CurrentChromeParrot()` только в том же изменении, где новый
   профиль и evidence проходят соответствующие тесты.
6. Пройдите локальные проверки, обязательный удалённый CI и независимое review.
7. Отдельно проверьте версии зависимостей потребителей: новая версия этого
   репозитория не меняет уже собранный бинарь автоматически.

Не меняйте ожидаемые байты только ради зелёного теста. При отсутствии нового
захвата корректный статус свежести — «не подтверждено».

Смысл differential evidence описан в
[объяснении](../explanation/browser-evidence.md); точная семантика accessor — в
[справке](../reference/browser-profile.md).
