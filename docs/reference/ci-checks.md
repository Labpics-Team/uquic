# Свойства CI

Обязательный результат `CI` учитывает все задания из проверяемого commit.
Отсутствие задания в зависимостях результата, ошибка или пропуск завершают CI
отказом. Обновления закреплённых actions и названий шагов не меняют эти свойства.

Версии компилятора следуют минимуму из `go.mod` и текущему патчу той же серии.
Нативная матрица сохраняет ОС, race, 32-bit и режимы протокола. Её команды строит
`ci/run-native-tests.sh`: каждый вызов получает свои параметры и окружение, без
переноса флагов через `GITHUB_ENV`. Флаги Go и настройки пользователя на раннере
не могут сужать проверяемые пакеты, менять выбранный компилятор или переводить
нативную сборку в другую ОС и архитектуру. 32-bit выбирается только своей строкой.

Обычные Go-проверки CI в `.ci` выполняет отдельное задание; штатный поиск Go и
Ginkgo не обходит этот каталог. Ginkgo запускает продуктовые unit suites без
дополнительного фильтра по имени пакета. Имя CLI в тестовых данных не меняет runner.

Trivy скачивается через API по неизменному asset ID и проверяется закреплённой
контрольной суммой. Он проверяет зависимости, конфигурацию и секреты всего checkout. Найденное
исправление принятой уязвимости снова блокирует CI; секреты в тестах, примерах
и Markdown проверяются на всех уровнях важности. Нативная контрольная находка
отличает рабочий сканер от ошибки инструмента. govulncheck проверяет достижимые
уязвимости основного и вложенного Go-модуля.

`go test -count=1 ./.ci` исполняет реальный Bash с небольшими CLI-подменами,
наблюдает аргументы, окружение и отказ. YAML anchors и aliases разбирает
`yaml.v3`; проверяются значения. Полные копии заданий и обязательное равенство
названий, команд и текущих версий инструментов не используются.
